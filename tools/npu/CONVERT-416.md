# Как получить модель 416/320 (на x86-ПК)

Текущий runtime читает размер входа **из самого `.nb`** (`640x640x3` сейчас).
Поэтому для ускорения достаточно положить рядом `.nb`, собранный Acuity с
входом 416 или 320 — код менять не нужно.

Собрать `.nb` можно только на **x86-64 Linux**: Acuity из
`aml_npu_sdk-ddk-6.4.8.7` — x86-утилита. На самой плате (ARM) её нет, qemu без
binfmt и часов эмуляции не подходит.

## 1. Экспорт ONNX с нужным входом

```bash
pip install ultralytics onnx onnxsim
yolo export model=yolov8n.pt imgsz=416 format=onnx opset=12 simplify=True
```

Получится `yolov8n.onnx` со входом `1x3x416x416`.

## 2. Конвертация Acuity

```bash
cd aml_npu_sdk-ddk-6.4.8.7/acuity-toolkit/bin
./convert \
  --model-name yolov8n_416 \
  --platform onnx \
  --model ./yolov8n.onnx \
  --mean-values '0 0 0 0.00392156' \
  --quantized-dtype asymmetric_affine \
  --source-files ./data/dataset/dataset0.txt \
  --kboard VIM3 --print-level 1
```

`dataset0.txt` — список калибровочных картинок. Для робота лучше собрать
10–50 кадров с реальной камеры (разные освещения), а не стандартный пример.

Результат: `yolov8n_416.nb`.

## 3. Копирование на плату

```bash
scp yolov8n_416.nb pi@<board>:/home/pi/opencv_projects/test_dnn_prj/tools/npu/
```

Запуск — как обычно, runtime сам увидит новый вход:

```bash
./run_npu.sh --npu-nb --capture-fps 30 --fast-resize
```

В логе будет:

```text
[NPU-NB] вход: 416x416x3 UINT8 planar BGR
[NPU-NB]   выход[0]: 52 52 144 1
[NPU-NB]   выход[1]: 26 26 144 1
[NPU-NB]   выход[2]: 13 13 144 1
```

Постобработка уже использует сетки из `.nb`, поэтому 52/26/13 работают без
изменений в коде.

## Ожидаемая скорость

| Вход | Граф на NPU | Полный кадр (оценка) | Детекций/с |
|---|---|---|---|
| 640 | ~24 мс | ~34–41 мс | ~20 |
| 416 | ~10–12 мс | ~18–22 мс | ~45–55 |
| 320 | ~6–8 мс | ~12–15 мс | ~65–80 |

Оценка сделана по площади входа: 416 — это 42 % пикселей от 640, 320 — 25 %.
Точные цифры зависят от модели и памяти.

## Альтернатива без ПК

Если 416 собрать негде, можно взять готовую более лёгкую модель из примеров
Khadas (например, MobileNet-SSD 300) — она тоже запускается этим runtime'ом,
но потребует своего постпроцессинга (SSD-якоря) и уступает YOLOv8n по
качеству.
