# Два потока и 120 fps

Приложение перестроено по образцу `main_ref.cppref`: отдельный поток непрерывно
читает камеру, а второй берёт **только самый свежий** кадр (устаревшие
отбрасываются). Тяжёлые операции (конверсия YUYV→BGR, инференс, окно) больше не
тормозят захват.

## Как это устроено

- Поток захвата: `grab()` + `retrieve()` без конвертации
  (`CAP_PROP_CONVERT_RGB=0`, `CAP_PROP_BUFFERSIZE=8`), кадр кладётся в слот
  «последний» через `std::swap` (без лишних копий).
- Поток обработки (главный): забирает последний кадр, конвертирует в BGR,
  раз в `--detect-every` кадров делает forward, рисует и показывает окно.
- Каждую секунду печатается `[PERF]` / `[EST]`: частота захвата, частота
  конвейера, число пропущенных кадров.

Камера (OV08A10, 1920×1080) отдаёт **~120 fps** в любом формате — проверено
`v4l2-ctl --stream-mmap` (119.4–120.0 fps для GREY/YUYV/RGB3).

## Команды

```bash
# Пиковый fps (два потока, без конверсии/инференса/окна)
./build/src/facedetection --estimate-only --grey --duration 10

# Только захват + конверсия + показ, без инференса
./build/src/facedetection --no-detect --no-gui --duration 10

# С окном, уменьшенным до 960 px (полный 1080p просаживает захват)
./build/src/facedetection --view-width 960

# NPU (TIM-VX/INT8) — как раньше, через скрипт
./run_npu.sh --npu --no-gui --duration 10
```

Новые ключи: `--estimate-only`, `--no-gui`, `--no-detect`,
`--detect-every <N>` (по умолчанию 50), `--grey`, `--view-width <px>`.

## Замеры (1920×1080)

| Режим | Захват | Конвейер |
|---|---|---|
| `--estimate-only` YUYV | 116.9 fps (пики 120.5) | 116.9 fps |
| `--estimate-only --grey` | **119.2 fps** (устойчиво 120.1) | 119.2 fps |
| `--no-detect --no-gui` | 116.2 fps | 109.1 fps |
| окно 1080p, без инференса | 85.3 fps | 17.6 fps |
| окно 960 px, без инференса | 102.6 fps | 33.6 fps |
| окно 960 px + CPU-инференс | 109.9 fps | 11.4 fps |

Вывод: **120 fps достигаются** в потоке захвата (режимы `--estimate-only`,
`--no-gui`). Инференс YOLOv8n занимает ~1.4 с на CPU, поэтому частота
*обработки* ограничена моделью — но захват при этом не останавливается
(в NPU-прогоне захват держал 113 fps, пока forward блокировал обработку).

## Сборка

`std::thread` требует pthread. `src/CMakeLists.txt` не менялся — флаг
передаётся через кэш CMake:

```bash
cd build
cmake -DOpenCV_DIR=/usr/local/opencv-4.12.0/lib/cmake/opencv4 \
      -DCMAKE_CXX_FLAGS="-pthread" -DCMAKE_EXE_LINKER_FLAGS="-pthread" ..
make -j4
```
